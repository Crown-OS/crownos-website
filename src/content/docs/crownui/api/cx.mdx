`Cx` owns the window's reactive runtime and its element tree. It derefs to `Runtime`, so `cx.signal(..)`, `count.get(cx)` and `count.set(cx, ..)` all work on it directly. Every other method talks to the view or to the platform.

You receive `&mut Cx` in these places:

- the closure of `component(|cx| ..)`, once, while the view is built,
- every event handler, such as `.on_click(|cx, event| ..)`,
- the completion of `cx.spawn`, `cx.request_animation_frame`, `cx.read_clipboard` and `cx.start_drag`,
- listeners such as `cx.on_close_requested` and `cx.on_app_windows`,
- `Kind::mount` and app tool handlers.

`bind`, `memo`, `effect` and `canvas` painters receive `&mut Runtime` instead. They read and write signals but cannot call the methods on this page that are not part of the runtime.

## Scope rules

Many methods tie what they create to the current scope: signals, effects, tasks, animation frames, close listeners, app icon listeners and app tools. When that scope is disposed, they go away with it.

In a component body the current scope is the component's own. In an event handler it is the window's root scope, because handlers do not switch scopes. So a task spawned from `on_click` is not cancelled when the component unmounts. Write its result with `try_set`, or spawn from the body.

## Scopes and diagnostics

Also from `Runtime`. App code rarely calls these. Components and tests do.

<ResponseField name="create_scope" type="fn(&mut self) -> ScopeId">

## Async work and timing

<ResponseField name="spawn" type="fn<T: Send + 'static>(&mut self, impl Future<Output = T> + Send + 'static, impl FnOnce(&mut Cx, T) + 'static) -> TaskId">
  Runs a future off the UI thread and calls the second closure with its output on the UI thread. The task is cancelled when the current scope is disposed first. See [Async](/docs/crownui/async).
</ResponseField>

<ResponseField name="request_animation_frame" type="fn(&mut self, impl FnOnce(&mut Cx, Duration) + 'static)">
  Calls the closure with the frame time just before the next frame is laid out, like the DOM's `requestAnimationFrame`. Ask again from inside it to run every frame. Dropped when the current scope ends first. Use it for simulations and values that drive layout. Use `.transition(..)` for everything else.
</ResponseField>

<ResponseField name="with_animation" type="fn(&mut self, impl Into<Curve>, impl FnOnce(&mut Cx))">
  Runs the closure so every property change it causes animates with the curve, like SwiftUI's `withAnimation`.
</ResponseField>

```rust
button("Expand").on_click(move |cx, _| {
    cx.with_animation(Spring::snappy(), |cx| expanded.set(cx, true))
})
```

## Window and display signals

Each returns a signal the view keeps up to date. Read it inside `bind` to react to changes.

<ResponseField name="color_scheme" type="fn(&self) -> Signal<ColorScheme>">
  The window's light or dark scheme. It drives `.dark(..)` variants and is also provided in the root scope's environment.
</ResponseField>

<ResponseField name="scale_factor" type="fn(&self) -> Signal<f32>">
  Device pixels per logical pixel, so pixel art can be made at the size it shows.
</ResponseField>

<ResponseField name="output_size" type="fn(&self) -> Signal<Option<Size>>">
  Logical size of the output the window is on, once the platform reports it. Layer surfaces use it to place themselves against the whole screen.
</ResponseField>

<ResponseField name="platform_capabilities" type="fn(&self) -> Signal<Capabilities>">
  What the platform supports, such as `materials`, `popups` or `text_input`, so a component picks a fallback instead of relying on something absent.
</ResponseField>

```rust
let scheme = cx.color_scheme();
text(bind(move |rt| match scheme.get(rt) {
    ColorScheme::Dark => "Dark".to_owned(),
    ColorScheme::Light => "Light".to_owned(),
}))
```

## Clipboard

<ResponseField name="copy_to_clipboard" type="fn(&mut self, impl Into<String>)">
  Puts text on the system clipboard.

<ResponseField name="paste_from_clipboard" type="fn(&mut self)">
  Requests the clipboard's text. It arrives as a paste into the focused element.
</ResponseField>

<ResponseField name="set_clipboard" type="fn(&mut self, Vec<(String, Vec<u8>)>)">
  Offers the same content in several MIME types. An item in a text type is also offered under the other text types.

<ResponseField name="read_clipboard" type="fn(&mut self, &[&str], impl FnOnce(&mut Cx, Option<ClipboardData>) + 'static)">
  Reads the clipboard in the first of the MIME types it holds, best first. The closure gets `None` when it holds none of them.

```rust
    cx.read_clipboard(&["image/png", "text/uri-list"], move |cx, data| {

            pasted_type.set(cx, data.mime_type);
        }
    })
})
```

## Drag out of the window

<ResponseField name="start_drag" type="fn(&mut self, DragSource, impl FnOnce(&mut Cx, DragOutcome) + 'static) -> bool">
  Hands a drag source to the platform while the pointer button is held. Call it from a `dragstart` or pointer-down handler. The closure learns whether a target took the drag. Returns `false`, dropping both, while an earlier drag is still in flight.

## Window control

<ResponseField name="begin_window_move" type="fn(&mut self)">
  Lets the user drag the window by the element being pressed. Call it from a pointer-down handler, as a client-drawn title bar does.
</ResponseField>

<ResponseField name="minimize_window" type="fn(&mut self)">
  Minimizes the window.
</ResponseField>

<ResponseField name="toggle_maximize_window" type="fn(&mut self)">
  Maximizes the window, or restores it when it already is.
</ResponseField>

<ResponseField name="request_close" type="fn(&mut self)">
  Asks to close the window the way its close button does. `on_close_requested` listeners can still keep it open.
</ResponseField>

<ResponseField name="close_window" type="fn(&mut self)">
  Closes the window without asking the `on_close_requested` listeners.
</ResponseField>

<ResponseField name="on_close_requested" type="fn(&mut self, impl FnMut(&mut Cx, &mut Event<()>) + 'static)">
  Calls the listener when the user or the compositor asks to close the window, until the current scope ends. `event.prevent_default()` keeps the window open. Without listeners the window closes right away.
</ResponseField>

<ResponseField name="set_idle_inhibited" type="fn(&mut self, bool)">
  Keeps the system from idling, such as screen blanking or sleep, while the window is visible. It is released with the window, so a crash cannot keep the machine awake.
</ResponseField>

```rust
cx.on_close_requested(move |cx, event| {
    if unsaved.get(cx) {
        event.prevent_default();
        confirm_open.set(cx, true);
    }
});

```

## Layer surfaces

Panels, docks and overlays run as layer surfaces. Toplevel windows ignore these two methods. See [Windows](/docs/crownui/windows).

<ResponseField name="set_keyboard_interactivity" type="fn(&mut self, KeyboardInteractivity)">
  Changes when the layer surface takes keyboard focus, for example `KeyboardInteractivity::OnDemand` only while a text field is open. Applied with the next frame.
</ResponseField>

<ResponseField name="set_layer_height" type="fn(&mut self, LayerExtent)">
  Resizes the layer surface along its height, for example to give a panel room only while it is open. Every pixel of surface costs GPU memory whether or not anything is drawn there. The new size arrives as a resize.
</ResponseField>

## App icons

A dock or launcher tells the compositor where it draws each app's icon, so windows open out of it and minimize into it.

<ResponseField name="set_app_icon" type="fn(&mut self, &str, Rect, f32)">
  Shows the icon of `app_id` at a rect with a corner radius, where it rests when the window is fully shown. Calling it again moves the icon. An unchanged placement sends nothing.
</ResponseField>

<ResponseField name="remove_app_icon" type="fn(&mut self, &str)">
  Stops showing the icon of an app.
</ResponseField>

<ResponseField name="activate_app_icon" type="fn(&mut self, &str) -> bool">
  Hands a click on an icon to the compositor, which restores and focuses the app's windows or asks `on_launch_app` listeners to start it. Returns `false` when the platform has no app icons or the window does not show this one, so the caller starts the app itself. The result is `#[must_use]`.
</ResponseField>

<ResponseField name="on_launch_app" type="fn(&mut self, impl FnMut(&mut Cx, &str) + 'static)">
  Calls the listener with the app id when the compositor asks to start an app whose icon was activated, until the current scope ends.
</ResponseField>

<ResponseField name="on_app_windows" type="fn(&mut self, impl FnMut(&mut Cx, &AppWindows) + 'static)">
  Calls the listener whenever an app's windows change, starting with every app already running. `AppWindows` has `app_id`, `count` and `focused`. A count of 0 means the app has no window left.
</ResponseField>

<ResponseField name="on_app_icon_lifted" type="fn(&mut self, impl FnMut(&mut Cx, &str, bool) + 'static)">
  Calls the listener with `true` when the compositor starts drawing an app's icon as part of a window's motion, and `false` when it stops. In between, the icon keeps its place but should not be drawn.
</ResponseField>

## Agents

<ResponseField name="register_tool" type="fn(&mut self, AppTool)">
  Exposes an action to AI agents over MCP while the current component stays mounted. `AppTool::new(name, description, input_schema, handler)` takes a handler of type `FnMut(&mut Cx, &str) -> Result<String, String>`, with JSON text in and out. Call `.destructive()` to make agents confirm first.

```rust
    r#"{"type":"object","properties":{}}"#,

        todos.update(cx, |list| list.retain(|todo| !todo.done));
        Ok("{}".to_owned())
    },

```

## Why one context

CrownUI has no globals and no interior mutability. Everything a handler can touch, from signals to the clipboard queue, lives in one value the UI thread owns, and you get it as `&mut Cx`. The borrow checker can then prove that nothing else is reading the tree while you change it, without a lock.

Most platform methods do not act right away. `copy_to_clipboard`, `request_focus`, `minimize_window` and the rest record a request, and the runtime carries it out after the handler returns. That keeps a handler free of I/O and lets tests run the same code against a headless platform.

The cost is that `Cx` is a wide type. It mixes reactive state, view building and platform requests in one place. Closures that only need state get `&mut Runtime` instead, which is why `bind` and `effect` cannot open a clipboard or move focus.
