<ApiExamples>
<RequestExample>
```rust title="Usage"
use crownui::prelude::*;

fn card(title: &'static str, body: &'static str) -> impl View {
    vstack((text(title).text_size(17.0).font_semibold(), text(body).text_color(rgb(0x64748b))))
        .gap(6.0)
        .p(16.0)
        .w_full()
        .rounded(14.0)
        .bg(WHITE)
        .border(1.0)
        .border_color(rgba(0x0f172a14))
        .shadow(Shadow::sm())
}
```
</RequestExample>

<ResponseExample>
```rust title="Signature"
pub trait Styled: Sized {
    fn modifier(self, modifier: Modifier) -> Self;
    // every other method is built on modifier and listed below
}

impl<K: Kind> Styled for Element<K> { .. }
impl Styled for VariantStyle { .. }
```
</ResponseExample>
</ApiExamples>

`Styled` is the trait behind every style method. Its methods are Tailwind class names that take literal values in logical pixels, or signals and `bind` closures for values that change.

Every widget returns an `Element<K>`, so every widget has these methods. `VariantStyle` implements `Styled` too, which is why the closure in `.hover(|style| style.bg(..))` uses the same names. The `Listeners` and `Semantic` traits are implemented for every `Styled` type, so event and accessibility methods chain the same way.

Each call appends a modifier. Modifiers apply in order after the widget's own defaults, so the last call for a property wins. Read the [styling guide](/docs/crownui/styling) for a walkthrough and the [layout guide](/docs/crownui/layout) for how the layout methods combine.

## Value types

Methods that take `impl IntoProp<T>` accept a literal or a reactive source.

<ParamField name="f32" type="impl IntoProp<f32>">
  An `f32`, `f64`, `i32` or `u32` literal, a `Signal<f32>`, a `Memo<f32>` or `bind(move |rt| ..)` returning `f32`.
</ParamField>

<ParamField name="Color" type="impl IntoProp<Color>">
  A `Color` such as `rgb(0x3b82f6)`, `rgba(0x3b82f680)` or `WHITE`, or a signal, memo or `bind` returning one.
</ParamField>

<ParamField name="bool" type="impl IntoProp<bool>">
  A `bool`, or a signal, memo or `bind` returning one.
</ParamField>

<ParamField name="Vector" type="impl IntoProp<Vector>">
  A `Vector::new(x, y)`, or a signal, memo or `bind` returning one.
</ParamField>

<ParamField name="Material" type="impl IntoProp<Material>">
  A `Material` such as `Material::thin()`, or a reactive source of one.
</ParamField>

A bound value updates that single property when its inputs change. The component does not run again. Methods that take a plain `f32`, `u16`, `Shadow`, `CursorIcon` or `Vec<GridTrack>` take literals only.

## The modifier method

<ParamField name="modifier" type="fn modifier(self, modifier: Modifier) -> Self" required>
  Appends a raw `Modifier`. Implementors provide this one method and get every other method for free. Component libraries use it with `Modifier::Style(StyleProp::..)` for properties that have no named method.
</ParamField>

| Method | Signature | Tailwind |
|---|---|---|
| `grid` | `fn grid(self) -> Self` | `grid` |
| `grid_cols` | `fn grid_cols(self, u16) -> Self` | `grid-cols-*`, equal columns |

`grid_cols` and `grid_template_cols` also switch the box to grid layout, so `.grid()` is only needed for a grid with no explicit columns. `GridTrack` has three variants: `Length(f32)` in logical pixels, `Fraction(f32)` for a share of the free space like `1fr`, and `Auto` to fit the content.

## What each group costs

Layout methods (padding, margin, size, flex, gap, alignment, grid, position, `display_none`) rerun layout for the affected part of the tree when a bound value changes. Paint methods (background, border, ring, corners, shadow) skip layout and re-record the repaint boundary that holds the node. Opacity, transforms and backdrop blur also skip layout, and the render thread only composes the frame again. `hidden`, `z` and `top_layer` skip layout as well. Text methods reshape the text and rerun layout, because the text size can change. `overflow_hidden` and `overflow_scroll` touch both layout and paint.

The same split decides what a variant accepts. Variants take paint, transform and text properties and ignore layout properties. See [variants](/docs/crownui/api/variants).
