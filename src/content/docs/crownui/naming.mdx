title: Naming

---

CrownUI borrows its names from vocabularies you already know. Views are SwiftUI nouns, style methods are Tailwind classes, event listeners are DOM events, and test actions are Testing Library verbs. If you know the web name, this page gives you the CrownUI name.

```rust
button("Save")
    .px(16.0)
    .py(8.0)
    .rounded(8.0)
    .bg(rgb(0x2563eb))
    .hover(|style| style.opacity(0.9))
    .on_click(|cx, event| save(cx, event.modifiers.shift_key))
```

That snippet reads as `px-4 py-2 rounded-lg bg-blue-600 hover:opacity-90` plus `onclick`. Tailwind's spacing scale is gone. Every style method takes a literal value in logical pixels, so `.p(16.0)` is `p-4`.

## Views

| SwiftUI | CrownUI |
|---|---|
| `Text`, `Button`, `Toggle`, `TextField` | `text(..)`, `button(..)`, `toggle(on)`, `text_field(value, placeholder)` |
| `VStack`, `HStack`, `ZStack`, `Spacer`, `Divider` | `vstack(..)`, `hstack(..)`, `zstack(..)`, `spacer()`, `divider()` |
| `ScrollView`, `LazyVStack`, `LazyVGrid` | `scroll_view(..)`, `lazy_vstack(..)` or `lazy_list(..)`, `lazy_grid(..)` |
| `Image`, `Canvas` | `image(width, height, rgba)`, `svg(..)`, `icon(..)`, `canvas(..)` |
| `if` in a body, `ForEach`, `.id(..)` | `show(cond, \|\| then, \|\| otherwise)`, `for_each(items, key, row)`, `keyed(..)` |
| `@State` | `cx.signal(value)` |
| `withAnimation` | `cx.with_animation(curve, \|cx\| ..)` |

Every method lives on the `Styled` trait, so it works on every element. Values are logical pixels unless the row says otherwise.

| `pointer-events-none pointer-events-auto` | `.pointer_events_none() .pointer_events_auto()` |
| `invisible` | `.hidden(true)`, which keeps the element's space |
| `hidden` (CSS `display: none`) | `.display_none()` |
| `cursor-pointer` and other cursors | `.cursor(CursorIcon::Pointer)` |
| `transition duration-200 ease-in-out` | `.transition(Spring::snappy())` or `.transition(Curve::ease_in_out(200))` |
| `hover: active: focus: focus-visible:` | `.hover(\|s\| ..) .active(\|s\| ..) .focus(\|s\| ..) .focus_visible(\|s\| ..)` |
| `disabled: dark:` | `.when_disabled(\|s\| ..) .dark(\|s\| ..)` |
| CSS `@starting-style`, exit animations | `.enter(\|s\| ..) .exit(\|s\| ..)` |
| CSS top layer (popovers, dialogs) | `.top_layer()` |
| CrownOS frosted glass | `.material(Material::thin())` or `Material::thick()` |
| `requestAnimationFrame` | `cx.request_animation_frame(\|cx, now\| ..)` |

A few rows need a note.

- `.pointer_events_none()` and `.pointer_events_auto()` on a layer surface's root also decide the surface's input region. The boxes that opt in receive input. Everything else passes through to the window below.
- `.material(..)` asks the compositor to draw the glass. It takes a bound value, so you can fade it.
- `cx.request_animation_frame` steps motion on the UI thread. Use it only for motion that `.transition(..)` cannot express, such as a physics simulation or a value that drives layout.
- Variants take paint, composite and text properties. A layout property inside a variant is ignored with `CUI0201`. See [Errors](/docs/crownui/errors).

## DOM event to listener

Every listener lives on the `Listeners` trait. A handler receives `(&mut Cx, &mut Event<T>)`.

| DOM | CrownUI |
|---|---|
| `click dblclick contextmenu` | `.on_click .on_double_click .on_context_menu` with `event.modifiers.ctrl_key`, `.shift_key` and the rest |
| `pointerdown pointerup pointermove` | `.on_pointer_down .on_pointer_up .on_pointer_move` |
| `pointerenter pointerleave pointercancel` | `.on_pointer_enter .on_pointer_leave .on_pointer_cancel` |
| `wheel scroll` | `.on_wheel .on_scroll` |
| `keydown keyup` | `.on_key_down .on_key_up` |
| `input change submit` | `.on_input .on_change .on_submit`, with the text in `event.value` |
| `compositionupdate beforeinput` | `.on_text_input` |
| `focus blur` | `.on_focus .on_blur`, with `event.visible` for focus that arrived by keyboard |
| `dragstart drag dragend` for a pointer gesture | `.on_drag_start .on_drag .on_drag_end` |
| HTML drag and drop `dragenter dragover` | `.on_drag_over`, then `event.accept(mime)` or `event.accept_with(mime, DndAction::Move)` |
| HTML drag and drop `dragleave drop` | `.on_drag_leave .on_drop`, with `event.data`, `event.mime_type` and `event.action` |
| Starting an HTML drag | `cx.start_drag(DragSource { .. }, \|cx, outcome\| ..)`, ending in `DragOutcome` |
| `accesskey`, a keyboard shortcut | `.shortcut(keybind)`, which clicks the element while it is mounted |
| Touch and touchpad gestures (no DOM name) | `.on_long_press .on_pinch` |
| Media `seeking` | the kit `waveform(..)` option `.on_seeking(\|cx, position\| ..)` |
| `navigator.clipboard.write` and `read` | `cx.set_clipboard(vec![(mime, bytes)])` and `cx.read_clipboard(&[mime], \|cx, data\| ..)` |
| `navigator.clipboard.writeText` and `readText` | `cx.copy_to_clipboard(text)` and `cx.paste_from_clipboard()` |
| `element.scrollTo` and `scrollIntoView` | `ScrollHandle` with `scroll_to_offset`, `scroll_to_index` and `ensure_visible` |
| `beforeunload` | `cx.on_close_requested(\|cx, event\| event.prevent_default())` keeps the window open |
| `window.close()` | `cx.close_window()` |

`event.stop_propagation()` and `event.prevent_default()` work as they do on the web. Events bubble from the target to the root.

CrownOS adds a few window events with no DOM equivalent. They serve launchers and docks.

| What happens | CrownUI |
|---|---|
| The compositor asks a launcher to start an app | `cx.on_launch_app(\|cx, app_id\| ..)`, after `cx.activate_app_icon(app_id)` |
| The set of apps with windows changes | `cx.on_app_windows(\|cx, windows\| ..)` |
| The compositor starts or stops drawing a launcher icon during a window animation | `cx.on_app_icon_lifted(\|cx, app_id, lifted\| ..)` |

## Testing Library query and action

`crowntest`, the MCP `ui_act` tool and the screen reader bridge share one set of names.

| Testing Library | CrownUI |
|---|---|
| `getByRole('button', { name: 'Save' })` | `role(Role::Button).name("Save")` |
| `getByText('Saved')` | `text("Saved")`, which matches a substring of the name or value |
| `queryAllByRole` | `app.count(role(Role::Button))` |
| `user.click user.dblClick user.hover` | `app.click(..) app.double_click(..) app.hover(..)` |
| `element.focus()` | `app.focus(..)` |
| `user.type user.keyboard` | `app.type_text("milk") app.press_key("Ctrl+S")` |
| `fireEvent.scroll`, a drag | `app.scroll(query, dy) app.drag(query, x, y)` |

## Why borrowed names, and what they cost

A name you already know needs no lookup. Someone who writes Tailwind reads `.items_center().justify_between()` without opening a manual. Someone who writes React reads `.on_click` and `event.stop_propagation()` the same way. AI agents gain the same way. They learned Tailwind, the DOM and Testing Library from public code, so they guess CrownUI's names right without a manual.

The rule is one obvious name per thing. When a concept has a web name, CrownUI uses it, adapted to Rust: `snake_case` and no hyphens. When it has none, as with compositor glass or app icons, CrownUI picks a plain descriptive name and adds a row here.

The cost is that the borrowed names bring borrowed expectations, and a few of them do not hold.

- Tailwind's spacing scale is gone. `.p(16.0)` is 16 logical pixels, not 16 steps. Literal values keep the code exact and make the type `f32`, so a bound value like `.p(bind(..))` works the same way.
- `hidden` follows SwiftUI, not Tailwind. `.hidden(true)` keeps the space, like Tailwind's `invisible`. Use `.display_none()` for Tailwind's `hidden`.
- Some Tailwind utilities have no method yet. Add one with the recipe in `AGENTS.md`, then add its row to this page in the same change.
- Variants are closures, not prefixes, so `hover:bg-blue-700` becomes `.hover(|style| style.bg(..))`. That costs a few characters, and in return the compiler checks every property inside the variant.
